# 收藏夹复习排序

收藏夹顺序由服务器保存，所有练习模式共享同一份排序快照。读取用户数据时检查快照：第一次读取或距生成时间满 8 小时，重新计算；其他情况下保留顺序。点击原来的重新生成按钮会先上传待同步的练习记录，再强制重排并从第一题开始，重新计时 8 小时。完整练完一轮本身不会强制重排。

新增词追加到现有快照末尾，删除词从快照移除，已有词的相对顺序保持不变。进度带上排序生成时间，过期进度不能恢复旧顺序。服务端用收藏夹行锁串行化快照生成，避免多个客户端同时生成不同顺序。

## 记忆模型与队列规则

使用 [ts-fsrs](https://open-spaced-repetition.github.io/ts-fsrs/) 的默认 FSRS 参数，目标保持率 90%，关闭随机扰动。模型根据实际复习间隔和结果更新稳定性、难度及预计回忆概率，未进行用户个人参数训练。

- 首次答错或点击“忘记了”：Again；同一题改对后不再记作一次成功复习。
- 主动查看音标后答对：Hard；未主动查看音标直接答对：Good。
- 仅展示题目不会作为成功或失败的复习。
- 每次结果保存 UUID 和实际发生时间；重试不会重复更新记忆，离线结果按时间排序重放。
- 跨收藏夹转移保留记忆状态和历史。

FSRS 负责记忆估计，应用负责生成完整练习顺序：到期词优先，结合相对逾期时长、遗忘概率、距上次复习的时间及难度排序；每 4 个到期词穿插 1 个未学词，其余未学词随后，未到期词最后。所有词都保留在队列中。

应用强制将最长复习间隔限制为 90 天；长期未见的熟词也进入到期队列，逾期权重持续增长。90 天是本应用的产品默认值，不是 FSRS 的通用要求。顺序在 8 小时内固定，因此 FSRS 短期复习时间不会中途插队；下次生成快照时才体现新优先级。

历史数据只有累计正确/错误次数，无法还原真实间隔。首次接入按平滑后的历史正确率初始化难度和最多 3 天的保守稳定性，不虚构历史复习事件；后续使用真实结果更新。旧客户端上传的累计次数仍兼容，但不能提供完整的 FSRS 事件历史。

## 数据库与验证

发布应用前运行 `bun run db:setup`，应用 `database/schema.sql` 中幂等的新增字段。新增字段保存收藏夹快照、生成时间、复习事件、初始状态、当前 FSRS 状态以及进度对应的快照时间。迁移不会删除原有收藏和练习统计。

算法测试：`bun test src/lib/vocabulary-practice/collection-order.test.ts`。
